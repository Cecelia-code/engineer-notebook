# 我常用的命令行习惯

很多效率提升不是来自更复杂的工具，而是来自更稳定的路径。

## 先从搜索开始

`rg` 很适合做代码搜索和笔记搜索，因为它足够快，结果也清楚。

```bash
rg "useEffect" src
rg "TODO|FIXME" .
rg --files content
```

## 把重复动作收口

如果一件事你三天内做了三次，就值得考虑变成脚本：

- 本地预览
- 生成静态文件
- 批量整理目录
- 启动调试环境

## 记录“为什么这样做”

光记命令本身意义不大。  
更有价值的是写明：

- 这个命令解决什么问题
- 适合在哪个场景使用
- 有没有风险或副作用

## 一个适合博客长期维护的做法

把博客写作也纳入工作流：

1. 新建一个 Markdown 文件。
2. 写标题、摘要、标签和日期。
3. 本地构建预览。
4. 调整格式后再发布。

这样内容的产出成本会低很多，也更容易坚持。
